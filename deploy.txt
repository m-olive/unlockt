UNLOCKT - AWS DEPLOYMENT NOTES
Deployed 2026-09-03 to https://m-olive.dev


WHAT WAS DEPLOYED

AWS Lightsail instance, Ubuntu 24.04, 2 GB RAM / 2 vCPU / 60 GB, us-east-1a,
static IP 3.238.34.100. Four containers via docker compose:

  caddy      - TLS termination, ports 80/443, reverse proxy to nginx
  frontend   - nginx serving the built Vite dist, /api proxied to :8080
  backend    - Spring Boot on :8080
  database   - MariaDB 11.2, data in the mariadb_data named volume

All four use network_mode: host, so they address each other over localhost.


WHY LIGHTSAIL AND NOT ECS/FARGATE

The compose stack already worked locally with host networking and localhost
proxying. Lightsail runs it unchanged. ECS would have meant ECR pushes, task
definitions, an ALB with target groups, ACM, and rewriting the nginx proxy_pass
off localhost - a day of new AWS surface for a demo that fits on one box.
Cost: no independent scaling, no rolling deploys, one instance is the whole app.

Flat ~$12/mo after the 3-month free window. Note Lightsail bills a stopped
instance; only deleting it stops the meter.


WHY THE DATABASE IS A CONTAINER, NOT RDS

Zero extra AWS services and the compose file stays intact. The named volume
survives compose down/up, image rebuilds, and reboots - it dies only to
`docker compose down -v`. RDS would survive instance loss, but for a graded
demo the snapshot covers that.

Consequence worth remembering: docker-entrypoint-initdb.d runs ONLY when
/var/lib/mysql is empty, i.e. first boot ever. Good - unlockt-schema.sql opens
with DROP DATABASE and can never fire on a redeploy. Bad - editing the schema
file after first boot has no effect on the live DB.


WHY CADDY

Automatic Let's Encrypt certificates and renewal with no certbot and no cron.
Cost: it must own ports 80 and 443, so nginx moved to 8081. The caddy_data
volume is load-bearing - it holds the cert and the ACME account key, and
without it every restart re-requests a cert and burns the Let's Encrypt rate
limit (5 per domain per week).

HTTPS was not optional: navigator.clipboard is undefined on a non-localhost
HTTP origin, so the Paste button on Link Steam silently disappears without TLS.


OBSTACLES

1. SSH key not attached at instance creation.
   Clicked through the create wizard too fast. Fixed by downloading the region
   default key and appending the real ed25519 public key to authorized_keys.

2. "Server accepts key" but Permission denied.
   Looked like a server problem, was a client one: the local ed25519 key is
   passphrase-protected with no ssh-agent running. Non-interactive sessions use
   the passphrase-free Lightsail .pem via an ~/.ssh/config alias.

3. Edited the wrong DNS record.
   The IP went onto _domainconnect (a GoDaddy internal helper) while the A @
   record still pointed at GoDaddy Website Builder. Symptom was a persistent
   "launching soon" page. Querying the authoritative nameserver directly
   (dig @ns43.domaincontrol.com) is what separated "wrong record" from
   "still propagating".

4. Propagation looked broken but wasn't.
   The parked record had a 1-hour TTL, and lowering a TTL is not retroactive -
   caches keep the old answer for the full original hour. Authoritative was
   correct within seconds.

5. .dev is HSTS-preloaded.
   Browsers refuse plain HTTP on .dev entirely, so nothing was visible at all
   until TLS worked. Certificate issuance was unaffected - Let's Encrypt
   validates server-to-server and ignores browser HSTS policy - but it removed
   the ability to sanity-check over http:// mid-setup. A .com would have been
   easier to debug.

6. A false "it works" from a stale local DNS cache.
   curl returned 200 over HTTPS while port 443 was still firewalled. The tell
   was the certificate issuer: GoDaddy, not Let's Encrypt. Every later check
   used --resolve to bypass DNS.

7. Port 443 not open by default. Lightsail opens 22 and 80 only.

8. docker-compose.yml had image: keys but no build: keys.
   Fine locally where images were built by hand; on the server compose went
   looking on Docker Hub. Images are currently built on the box with
   docker build. Adding build: keys would make `docker compose up --build`
   the whole deploy.


STILL OPEN

- ddl-auto=update, not validate. Hibernate can now silently alter a database
  that matters, and unlockt-schema.sql stops being the source of truth.
- Port 3306 published on 0.0.0.0. The Lightsail firewall is the only thing in
  front of a MariaDB whose password is "dbeaver". Bind it to 127.0.0.1.
- Seed data: the init-time seed inserted 13 games but 0 library entries,
  because unlockt-seed.sql resolves users by email and no users existed yet.
  Runbook order matters: register accounts -> unlockt-seed.sql ->
  warm-achievements.sh https://m-olive.dev -> unlockt-seed-achievement-ratings.sql
- Sessions are in-memory, so this must stay a single instance.
- Disk snapshots of a running MariaDB are crash-consistent, not clean. Take a
  mysqldump before demoing.
